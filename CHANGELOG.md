All notable changes to this project are recorded here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/) while in pre-1.0 development.

## [Unreleased]

### v0.1 Beta summary (pushed to `main`, not tagged)

This section summarises everything below for the first public beta. No version tag or release has been created.

- **Five skills:** `vyson-css-motion` (pilot), `vyson-premium-website-design`, `vyson-3d-interactive-web`, `vyson-frontend-development` and `vyson-website-quality-engineering` (drafts). Each has an example in `examples/`, an eval file in `evals/` and its own checker script. All five pass the skill validator in strict mode.
- **Verified:** `npm run check` (automated tests, template and skill validation, Markdown link check), the checkers on their example sites, the examples in headless Chrome, the installer from a local folder, and, after the push (commit `dd92dbb`), `--list` and `--skill '*'` on the public GitHub repository, which found and installed all five skills into `.agents/skills/` and `.claude/skills/` in a temporary folder (telemetry off). `vyson-css-motion` alone was also installed from GitHub on 10 November 2026. That is file installation only.
- **Not verified:** any agent loading or following a skill; running the eval files with an agent; Firefox, Safari, a real phone or GPU, a screen reader, Linux and macOS; installing each of the four newer skills on its own from GitHub; `skills update`; React and Vue helpers outside Node; Next.js and Nuxt; independent external testing.

### Added
- **Zero-terminal install by prompt (decision 15).** `docs/install.md` holds one copy-paste install prompt (also in the README) that makes the user's agent download `skills-manifest.json` and only the named skills from the public GitHub repository, verify every file's size and sha256 in a temporary folder, copy the verified folders into the agent's project skills folder without overwriting a different copy, report honestly, then read the installed `SKILL.md` and start the work in the same chat. Works for one skill, several, or all five; installs only the named skills. `skills-manifest.json` is generated by `tools/build-manifest.mjs` (`npm run build:manifest`, checked by `npm run check:manifest` and a test). Reference implementation and developer route: `node tools/install-skills.mjs --from-github [--ref] [--base-url]`. Antigravity added to the agent table (`antigravity`, alias `agy`; project folder `.agents/skills/`, global `~/.gemini/config/skills/`; documented only, untested). Integration guide: `integrations/antigravity.md`. Installer hashes now ignore Windows line endings in text files, so an identical copy on Windows is not reported as a conflict. The clone-and-copy install stays, documented for developers. Tests: `tools/test/manifest.test.mjs`, `tools/test/github-install.test.mjs`, `tools/test/install-prompt.test.mjs`. **Not verified:** no agent has run the prompt against the published repository, and Antigravity was not tested at all.
- Project-level skill copier `tools/install-skills.mjs`: agent-specific folders (Cursor `.cursor/skills/`, Claude Code `.claude/skills/`, Codex `.agents/skills/`), missing-directory creation, one skill or all five, no overwrite of different existing files, no global install without `--global --confirm-global`, hash verification, and an onboarding report that keeps **file install** separate from **agent discovery** (always pending until a new session lists the skill). Mapping and Cursor finding: `integrations/agents.md`. Tests: `tools/test/install-skills.test.mjs`.
- **Ready-to-use workflow for all five skills (decision 14).** Each `SKILL.md` now has a "How this skill runs" section: understand, plan internally, implement, verify, present, in one pass, asking only when blocked and keeping safeguards for commits, pushes, deploys, deleting or replacing user files, real submissions and paid or tracking services. Each skill gained `references/workflow.md` (defaults it decides alone, plain HTML, React, Next.js and Vue placement, hand-off format, an invented worked example) and `references/prompt.md` (the one prompt to paste). The five prompts are collected in `docs/five-prompts.md`; the skills share the hand-off file `VYSON-NOTES.md`, one section each. Wording that made skills stop and wait for approval was removed from the skills and their references. The quality skill now also runs the four sibling checkers. The installer prints the real prompt and the path of all five. A new eval case per skill covers "do the whole job without questions". Tests: `tools/test/workflow.test.mjs`. **Not verified:** no agent has followed the five prompts end to end.

- Example site `examples/vyson-css-motion/` and eval file `evals/vyson-css-motion/evals.json` (cases written, not yet run with an agent).
- Tests for the motion checker and for the skill's own files.
- Pilot experiment record `bench/experiments/css-motion-pilot-001/`: one with-skill and one without-skill run of the same task (**1 run per condition, known confounds, not proof of effectiveness**), the measuring scripts, results, representative screenshots, a blinded AI review and a human review sheet. Plan for a controlled three-repeat experiment (`bench/experiments/css-motion-repeat-plan.md`, not started).
- `vyson-css-motion` after the pilot review:
  - Recipe 7 (accordion): only one panel may be expanded at a time, opening one closes the other, full keyboard use (`Tab`, `Enter`, `Space`, arrows, `Home`, `End`), and the closing animation no longer plays on page load.
  - Tap-target rule: 44 by 44 CSS pixels to aim for on touch screens, never under 24 by 24 (WCAG 2.2 level AA, SC 2.5.8). Starter helper `.vy-tap`, advice in recipes 4, 6 and 7, and a console snippet that measures it.
  - New reference `references/verification.md` that keeps static checks and real browser tests apart, with manual browser steps and an accordion test.
  - `motion-lint.mjs` has five new static rules (ML010 scroll listeners, ML011 hover movement on touch screens, ML012 tiny controls, ML013 `aria-expanded` wiring, ML014 content hidden without a script gate), now also reads `.js` files and inline scripts, and says in every run that it is a static check and opened no browser.
  - The example site follows the new tap-target and accordion rules.
  - Simulated tests (a fake page, not a browser) for the accordion logic of the recipe and of the example, and static tests for the tap-target rule.

- Draft skill `vyson-premium-website-design` (design pillar): a method for choosing a visual direction and building a distinctive, premium-looking site, with six reference files (visual direction, layout and hierarchy, typography and spacing, colour and imagery, responsive design and details, quality checks), a starter file `assets/design-tokens.css`, and a static checker `scripts/design-lint.mjs` (18 rules, DL001 to DL018: language, viewport, alt text, headings, landmarks, focus outlines, tiny text, placeholder text, links to nowhere, contrast of the token colours, font stacks, files from other websites, `100vw`). The checker is a static check and is not a design review. The skill adds no animation and hands motion requests to `vyson-css-motion`.
- Example site `examples/vyson-premium-website-design/` (a made-up architecture studio, no external files, no scripts, no animation), with an honest record of what was and was not checked. It was written by an AI agent in the same session as the skill, so it is not an independent test. Eval file `evals/vyson-premium-website-design/evals.json` (cases written, not run with an agent).
- Tests `tools/test/design-lint.test.mjs` (the checker) and `tools/test/skill-vyson-premium-website-design.test.mjs` (the skill's files agree with each other).

- Draft skill `vyson-3d-interactive-web` (3D pillar): decide whether 3D earns its place, choose the lightest approach (CSS, 2D canvas, plain WebGL, Three.js), then build with a performance budget, a fallback ladder (`high`, `low`, poster, no WebGL), reduced-motion handling and context-loss handling. Four reference files, a starter file `assets/canvas-stage.js` (render loop that pauses off screen and in hidden tabs, pixel-ratio and total-pixel caps, context loss), a local server `scripts/serve.mjs` (127.0.0.1 only) and a static checker `scripts/3d-lint.mjs` (14 rules, TD001 to TD014). Example `examples/vyson-3d-interactive-web/` (a made-up glass paperweight in plain WebGL, no model files) was checked in headless Chrome with **software-rendered WebGL only**, so it says nothing about GPU speed or phones. Eval file written, not run with an agent.
- Draft skill `vyson-frontend-development` (frontend pillar): HTML that works first, forms with inline validation and an error summary, data loading with loading, empty, error and success states, widgets, safe DOM updates and security hygiene. Four reference files at first (a fifth, `frameworks.md`, was added later; see the framework entry below), two helper modules (`assets/fetch-state.js`, `assets/form-helpers.js`) and a static checker `scripts/frontend-lint.mjs` (15 rules, FD001 to FD015, with `// vyson-ok: FDxxx reason` suppression). Example `examples/vyson-frontend-development/` (a made-up workshop programme with a searchable list, a dialog, a sign-up form and demo controls for slow, empty and failing responses; nothing is sent anywhere). Vite (MIT) is recorded in `THIRD_PARTY.md`. Eval file written, not run with an agent.
- Draft skill `vyson-website-quality-engineering` (quality pillar): plan a launch check, run a static audit, run a real-browser check, do the manual checks a tool cannot do, fix, re-run, and write a report that keeps static audit, browser test and manual checks apart. Four reference files and two tools: `scripts/site-audit.mjs` (static, 28 rules, QA001 to QA028, checks file-name capital letters on every system) and `scripts/browser-check.mjs` (a real-browser test using an installed Chrome or Edge over the DevTools protocol, no downloads and no dependencies, 14 rules, BC001 to BC014: sideways scrolling, tap-target size, text size, console errors, failed requests, layout shift, keyboard focus, reduced motion, other websites). The example `examples/vyson-website-quality-engineering/` holds a flawed made-up bakery site, its repaired version, the unedited output of both tools before and after, screenshots and a filled-in report. Eval file written, not run with an agent.
- Tests for the new skills and tools: `tools/test/3d-lint.test.mjs`, `frontend-lint.test.mjs`, `site-audit.test.mjs`, `browser-check.test.mjs` (the real-browser tests are skipped when no Chrome or Edge is found, or when `VYSON_SKIP_BROWSER_TESTS=1`) and one `skill-<name>.test.mjs` per skill.

- Framework support in `vyson-frontend-development`: a `references/frameworks.md` (the same job in plain JavaScript, React, Next.js and Vue, mistakes per framework, which build-time settings are public), a React hook `assets/use-fetch-state.react.js` and a Vue 3 composable `assets/use-fetch-state.vue.js` built on `fetch-state.js`, and `.vue` support in `frontend-lint.mjs` (`<script>` blocks and `v-html`, rule FD002). The adapters were checked in Node with React 19.3.1 and its test renderer and with Vue 3.5.45 through `node tools/framework-checks/run.mjs` (installs the packages in a temporary folder, nothing in the repository). That is logic only: not a browser, Nuxt or Next.js test. `vyson-3d-interactive-web` has written, untested guidance for mounting its stage in Vue, React and Next.js.
- Reuse-first policy (`docs/decisions.md` decision 12, `AGENTS.md`, `CONTRIBUTING.md`, the pull request template): adapt open-source work only when a licence file permits it, keep the notice, and record it. `THIRD_PARTY.md` has a "Reference repositories reviewed" table (MengTo/skills, vercel-labs/agent-skills, shadcn-ui/ui, magicuidesign/magicui, and the Aceternity repository named in the request, which does not exist on GitHub) and an "Adapted material" table. One thing was adapted: the "removal test" from MengTo/skills (MIT, Copyright (c) 2026 Meng To) into `vyson-premium-website-design`, with the licence text in that skill's `NOTICE.md`. Nothing was copied from the others (vercel-labs/agent-skills has no licence file, and shadcn-ui and Magic UI have their own skills and need React and Tailwind). Vue (MIT) was added to the list of libraries.

- `README.md`, `ROADMAP.md`, `skills/README.md`, `examples/README.md`, `evals/README.md`, `tools/README.md` and `integrations/README.md` describe all five skills. - Measuring script (pilot harness version 3): real hover test, a stronger scripts-off check, an accordion test, and no machine paths in result files. Version 2, which produced the first results, is kept in `archive/`.
- Public experiment files no longer contain personal Windows paths or user names. Screenshots were reduced to four representative, smaller images.
- `README.md` and `integrations/README.md` now record the test of installing `vyson-css-motion` from the public GitHub repository (10 November 2026, Skills CLI 1.7.6, Windows 10, project-level install). `--list` found exactly one skill, the default and the explicit installs passed, and the installed files passed the validator and the motion linter. The recommended command is pinned to the tested version (`npx skills@1.7.6 add ...`), and the unpinned form is shown as an untested alternative. The default-install test ran in an agent terminal, so normal interactive terminal behaviour is untested. The installed files had CRLF line endings because of Git's checkout settings on the Windows test PC, and their content otherwise matched. This shows where files end up, **not** that Cursor, Claude Code or Codex loads or follows the skill (untested). macOS, Linux, global install, symlink mode, update, check, remove and other Skills CLI versions are untested.

It also explains the installer's telemetry as described by the installer's own documentation (on by default; setting `DISABLE_TELEMETRY=1` or `DO_NOT_TRACK=1` turns it off). These controls belong to the third-party installer, and we have not audited it or observed its network traffic. `README.md` shows a short telemetry note, with both PowerShell opt-out commands, directly under the install command.
